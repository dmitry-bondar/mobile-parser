# Шаблон Android и временные потоки

Код и конфиги обновляются через Git. Сам настроенный Android переносится отдельным **закрытым** архивом, не через GitHub. Архив содержит установленные приложения, данные и сессии; он не зашифрован. Храните и передавайте его только доверенным способом. SHA-256 проверяет целостность, но не заменяет доверенный источник или шифрование.

Команды рассчитаны на Windows x64, Node.js 22, PowerShell, установленный `tar.exe` (есть в Windows 10) и SDK проекта. Выполняйте из `C:\mobile-parser`. На сервере нужен тот же Play Store system-image **той же ревизии**: при установке свойства образа сверяются с архивом. Версию Emulator также желательно держать одинаковой. Авторизация может потребовать повторного входа — приложение или Google могут заметить перенос/одновременные сессии.

## 1. На своём ПК

Установите все нужные приложения в один AVD и войдите вручную. Например, текущий подготовленный AVD — `mobile-parser-playstore-api35-recovery`. Полностью выключите его. Во время упаковки не запускайте и не изменяйте шаблон.

```powershell
cd C:\mobile-parser
New-Item -ItemType Directory -Force private-avd
npm run avd -- pack mobile-parser-playstore-api35-recovery private-avd/android-v1.tar.gz
```

Упаковка копирует данные без snapshot/lock-файлов и превращает QCOW2-диски в независимые от исходных путей. Исходный AVD не изменяется. Нужен дополнительный свободный диск под рабочую копию и архив. Процесс может занимать несколько минут. Уже существующий архив не перезаписывается — используйте новое имя версии.

Получатся `android-v1.tar.gz` и `android-v1.tar.gz.sha256`. Передайте оба файла на сервер закрытым каналом в `C:\mobile-parser\private-avd`. Ни архив, ни исходные аккаунты не добавляйте в Git. Промежуточная папка `private-avd/export-*` сохраняется; после проверки архива её можно удалить вручную, убедившись в точном пути.

## 2. На сервере: установить шаблон один раз

```powershell
cd C:\mobile-parser
git pull --ff-only
npm ci
npm run avd -- install android-v1 private-avd/android-v1.tar.gz
```

Создаётся `android-avd/android-v1.avd` и его `.ini` с серверными путями. Существующий AVD не перезаписывается. Если SDK образа отличается, установка останавливается; не подменяйте ревизию в manifest. При обновлении используйте новую версию архива и новое имя AVD — например, `android-v2`. Промежуточная папка `private-avd/import-*` остаётся для диагностики и занимает место.

Желательно проверить установленное приложение на шаблоне вручную **до** запуска потоков:

```powershell
$env:ANDROID_AVD = 'android-v1'
$env:ANDROID_SERIAL = 'emulator-5554'
npm run android
```

Если нужен повторный вход — выполните его, затем штатно выключите шаблон. При работе потоков сам шаблон не запускайте. Клонирование сохраняет настройки CPU/RAM/экрана исходного AVD: настройте их один раз до упаковки (например, 2 CPU и 2048 МБ на устройство).

## 3. Каждый сбор — новые временные копии

Рекомендуемый запуск всех потоков **одной командой**, без отдельных окон:

```powershell
npm run pobeda:parallel -- android-v1 4
```

Команда запускает потоки с интервалом 25 секунд, показывает таблицу «поток / статус / обработано адресов / текущий адрес / категория / последняя ошибка» и ждёт завершения процессов вместе с очисткой временных AVD. Собственный шаблон `android-v1` предварительно должен быть выключен. Для двух потоков задайте `2` вместо `4`.

Общий каталог `outputs/pobeda/parallel-<время>-<id>/` содержит:

- `status.json` — обновляемый статус и итог по каждому адресу, число товаров, ошибки, время начала/окончания потока, код выхода и путь его результатов.
- `progress.jsonl` — история переходов и ошибок с номером потока и UTC-временем.
- `worker-1.log`…`worker-N.log` — полный вывод процессов, включая ошибки подготовки и очистки.
- `config.snapshot.json` — общий конфиг именно этого запуска; адреса распределяются без пересечения по позициям массива.

Статусы адресов: «Ожидает», «Собирается», «Готово», «Частично» (ошибки категорий), «Ошибка» (сбор адреса оборван), «Не запущен» (до него не дошли). Успех адреса отмечается только после сохранения `products.json`. Ошибка категории не мешает последующим категориям, но ошибка выбора магазина завершает его поток; остальные потоки продолжают независимо. Ошибка очистки делает итог потока ошибочным, но не отменяет успех уже собранных адресов.

После завершения выводится таблица всех адресов. Общий код 0 означает успех всех потоков и адресов; иначе 1. Каталог каждого экстрактора по-прежнему хранит его `run.log`, `events.jsonl`, JSON и PNG. `status.json` — отчёт выполнения, **не Excel-аналитика ресурсов**; замер CPU/RAM и общий Excel эта команда не делает.

Оставьте управляющую консоль открытой до окончания. В Windows Ctrl+C останавливает запуск следующих потоков, но команда ждёт уже запущенные — они заканчивают сбор и очистку. Принудительное закрытие окна/процесса или отключение сервера не гарантирует итоговый статус и очистку. Если у потока нет времени окончания в `status.json`, это последний сохранённый статус, а не доказательство, что он сейчас работает.

Ниже — прежний вариант отдельных команд для ручного запуска отдельных частей; при нём общей таблицы нет.

Откройте четыре PowerShell-консоли в корне проекта. Выполните по одной команде в каждой:

```powershell
# Консоль 1
npm run avd -- run android-v1 1 4
# Консоль 2
npm run avd -- run android-v1 2 4
# Консоль 3
npm run avd -- run android-v1 3 4
# Консоль 4
npm run avd -- run android-v1 4 4
```

Команды здесь именно для экстрактора Победы. Новые приложения можно включать в шаблон, но для их сбора всё равно нужен свой экстрактор; они не начнут собираться автоматически.

Основной конфиг автоматически распределяется между четырьмя потоками: сейчас по пять из 20 адресов. Ручные worker-configs не нужны. Через `POBEDA_CONFIG` можно передать другой полный конфиг для разбиения. Каждый поток получает уникальное имя `mp-run-UUID`, порт 5554/5556/5558/5560 и `outputs/pobeda/mp-run-UUID/` с копией своего конфига. Запускайте команды с интервалом 20–30 секунд, чтобы снизить пики копирования и загрузки.

После завершения (в том числе ошибки экстрактора) скрипт останавливает только свой AVD, ждёт выхода его процесса и удаляет только свою временную копию и `.ini`. Результаты, JSON, PNG и логи остаются. Шаблон не меняется. При неподтверждённой остановке копия сохраняется, команда сообщает ошибку. После отключения питания, принудительного завершения или Ctrl+C очистка не гарантируется: оставшиеся AVD и lock-файлы требуют ручной проверки. Не удаляйте их, пока процессы работают.

На один поток нужны свободные порты и дополнительное место размером с копию AVD. Уже занятый порт или lock-файл блокируют повторный запуск. Удаление выполняется только для сгенерированных `mp-run-UUID` непосредственно внутри `android-avd`; шаблоны и старые `pobeda-1`…`pobeda-4` автоматически не удаляются.

`private-avd/.template.lock` защищает упаковку/установку от одновременной операции. Если прошлый процесс аварийно завершился, сначала убедитесь, что операции нет, и только затем удалите этот конкретный lock. Аналогично для `android-avd/.port-emulator-N.lock`. При неудачной копии частичная папка может сохраниться для ручной проверки. Не запускайте поверх неё повторный импорт с тем же именем.

## Обновление приложений

На ПК обновите выключенный затем снова настроенный шаблон: включите его, установите приложение, войдите при необходимости, штатно выключите. Создайте `android-v2.tar.gz`, передайте архив и контрольную сумму, установите серверный `android-v2`. Код обновите отдельным `git pull --ff-only`. В командах сборов поменяйте только имя шаблона. Автоматической загрузки архива из облака нет: закрытый канал передачи выбирается вами.
