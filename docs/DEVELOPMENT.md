# Разработка и диагностика

## Устройство проекта

- `src/adb.ts` — запуск ADB, выбор устройства; таймаут отдельной команды 30 секунд.
- `src/android.ts` — загрузка AVD, XML UIAutomator, ожидания, нажатия и прокрутка.
- `src/logger.ts` — явная запись UTF-8 логов одновременно в файл и консоль, с UTC-временем и уровнем.
- `src/start-android.ts` — запуск Android без приложения и без выключения.
- `src/devices.ts`, `src/screenshot.ts` — отдельные диагностические команды.
- `src/extractors/pobeda/index.ts` — сценарий конкретного приложения; его адреса и категории находятся в соседнем `config.json`.
- `tests/` — проверки без подключения Android. `npm run check` проверяет TypeScript, `npm test` запускает тесты.

Проект работает через Android UI, а не внутренний API приложения. Appium, OCR и сервер не используются. Запуск — напрямую через `tsx`, сборка для работы не требуется.

## Контракт Победы

Объекты конфига обрабатываются последовательно. Сначала проверяется авторизация, затем адрес на главной сравнивается с конфигом через `matchesAddress`. При совпадении выбор магазина, поиск и установка/переключение ADBKeyboard пропускаются; используется адрес, показанный на главной. Если адрес не задан или отличается, проверка завершается ошибкой без смены магазина. Далее открываются пути категорий. Родительская категория обходится рекурсивно до всех листьев. Перед следующим магазином сценарий возвращается на главную.

Сопоставление адресов находится в `src/extractors/pobeda/address.ts`: регистр, `ё/е`, визуально похожие латинские буквы, пробелы и пунктуация нормализуются; `ул./улица`, `б-р/бульвар`, `пр-т/проспект` и другие типы улиц не влияют на сравнение. `д./дом`, `к./корп./корпус`, `стр./строение`, `пом./помещение` распознаются. Дом, буква, дробный номер, корпус и строение должны совпасть точно. Помещение допускается в выдаче, если оно не задано в конфиге; заданное помещение сравнивается точно. Произвольные опечатки и замена `/1` на `корпус 1` не допускаются.

Можно писать `ул. Молодёжная, д. 2 А`, `Молодежная,2А` или `Молодежная2А`. Для города используйте запятую или тип улицы: `г. Самара, улица Молодежная, д. 2А`. При указанном городе он тоже должен совпасть; без города выбирается первый подходящий адрес, поэтому для одноимённых улиц в разных городах уточняйте город. Только номер дома или улица без дома — ошибка конфига.

В рабочем конфиге заданы 20 магазинов, для каждого сохранены прежние 30 категорий. Адреса записаны без области и названий ТЦ, с обязательным городом. `3й` и `3-й` сопоставляются; префикс `ст` перед номером отдельного здания допускается как `д` (`Рязань, Окружная дорога 185 км, ст2а/4`). Километр дороги и полный номер `2а/4` должны совпасть; `стр.` после номера дома по-прежнему обозначает отдельное строение.

После проверки в приложении согласованы адреса `Рязань, М-5 Урал 185 км,2А.4`, `Орел, Ливенская,70`, `Курск, Дружбы,99А`, `Белгород, Шаландина,4Б.1`. Точка внутри номера сохраняется: `4Б.1` не совпадает с `4Б`, `4Б.2` или `4Б/1`. Для улицы с километром поисковый токен берётся до суффикса `185 км` (например, `урал`), но при сравнении адреса километр проверяется полностью.

Автоматический поиск магазина и установка ADBKeyboard удалены из экстрактора. Пользователь выставляет адрес вручную в постоянном профиле; все режимы запуска только сравнивают его с конфигом.

В `products.json` записывается массив:

```json
[
  {
    "name": "Название товара",
    "price": 109.9,
    "available": true,
    "category": "Мясо/Мясо птицы",
    "address": "Адрес, подтверждённый приложением",
    "screenshot": "store-1/Мясо-Мясо птицы-1.png"
  }
]
```

Цена в рублях; у отсутствующего товара она может быть `null`. Дедупликация — адрес + полный путь категории + название. Это не идентификатор товара: одноимённые товары внутри одной категории могут объединиться. Из списка не извлекаются изображения, штрихкоды и полные карточки товара.

`screenshot` — путь относительно папки сбора к PNG страницы, где найден товар, а не отдельная обрезанная карточка. При повторном обнаружении товара данные и ссылка обновляются последним экраном. Товары добавляются только после успешного сохранения PNG. Для старых сборов с одинаковыми основным и частичным JSON можно выполнить `npx tsx scripts/backfill-pobeda-screenshots.ts <папка-сбора>`: порядок первого добавления товаров и счётчики в `run.log` восстанавливают ссылки на первый экран. Скрипт проверяет категорию, адрес, счётчики и существование PNG, сохраняет оригиналы `*.before-screenshot.json`; при несогласованных данных восстановление отменяется.

`products.json` обновляется после каждого магазина. При перехваченной ошибке сохраняется накопленный `products.partial.json`. Скриншоты страниц лежат в `store-N/`. Нужная авторизация приводит к коду 1; успешная работа — коду 0. Выключение правильного AVD выполняется в `finally`, включая ошибку и отказ из-за авторизации. Принудительное завершение процесса/отключение питания не гарантирует выполнение `finally` или сохранение результатов.

## Логи

Экран «К сожалению, здесь пока пусто. Скоро добавим товары!» — валидная пустая конечная категория, в том числе без поля поиска/сортировки. В лог пишется «товаров нет», в метрики `leaf-end` с `empty: true`; ожидание товаров и прокрутка не выполняются. Произвольный пустой экран без такого сообщения по-прежнему не считается подтверждённым отсутствием товаров.

При выборе категории нажимается кликабельная плитка с нужным текстом, а не первое текстовое совпадение: заголовок и дочерняя плитка могут называться одинаково. После открытой дочерней категории выполняется «Назад», даже если её название совпадает с родителем. Повтор экрана среди предков считается циклом; глубина ограничена 20 переходами. Эти ошибки обрабатываются как ошибки категории, без бесконечной рекурсии.

Ошибки категорий и подкатегорий записываются со стеком и полным путём, сохраняется `products.partial.json`, обход продолжается. Возврат к родителю ограничен шестью нажатиями «Назад» и проверкой экрана. При неудачном возврате следующая категория конфига начинается с проверки корня каталога. Метрики: `category-error` и `configured-category-error`. Пропуски дают итоговый код 1. Ошибки подготовки Android и авторизации остаются критическими. Проверка адреса повторяется до трёх попыток с повторным открытием приложения; затем записывается store-error, адрес пропускается. Неподтверждённый магазин не собирается. Адреса автоматически не устанавливаются.

Победа: `outputs/pobeda/<UTC-время>/run.log`. Отдельный запуск Android: `logs/android-<UTC-время>.log`. Каждая запись содержит время ISO 8601, `INFO`/`ERROR` и сообщение; ошибки сохраняются со стеком. Логируются запуск, магазин, полный путь категории, страницы и общее накопленное число товаров, завершение и выключение эмулятора.

Запись синхронная: сообщения не остаются в очереди перед штатным выходом. Это журнал сценария, а не полный Android logcat/вывод процесса emulator; сообщения npm и ошибки загрузки модулей до создания logger в него не попадают. `devices` и `screenshot` выводят результат только в консоль. Логи и скриншоты могут содержать адреса и персональные данные; проверяйте их перед отправкой коллегам/ИИ. Автоматического удаления/ротации нет — следите за размером `outputs/`.

## Новый экстрактор

1. Добавьте `src/extractors/<name>/index.ts` и собственный конфиг с примером. Логику приложения храните внутри его папки.
2. Используйте `Android` и `createLogger` из общих модулей. Создавайте отдельный каталог результатов и `run.log` для каждого запуска.
3. Добавьте npm-команду `"<name>": "tsx src/extractors/<name>/index.ts"`.
4. Явно определите правила авторизации, адреса, каталога, результатов и владения эмулятором. Ошибки должны давать ненулевой код; восстановление клавиатуры и выключение нужного AVD — в `finally`.
5. Добавьте проверки, опишите конфиг и выполните живой прогон. Не переносите селекторы Победы в общие операции Android.

Не запускайте два сценария на одном устройстве одновременно: они перехватывают UI и используют общий `/sdcard/mobile-parser.xml`. Другой порт не изолирует изменяемое состояние одного AVD. Для независимых одновременных запусков нужны отдельные AVD и порты; задайте `ANDROID_AVD` и `ANDROID_SERIAL` каждому процессу. Пула устройств нет. По умолчанию используется `mobile-parser-playstore-api35-recovery`.

## Отладка

Из корня проекта:

```powershell
npm run android
npm run devices
npm run screenshot -- debug
& '.\android-sdk\platform-tools\adb.exe' -s emulator-5554 shell uiautomator dump /sdcard/mobile-parser.xml
& '.\android-sdk\platform-tools\adb.exe' -s emulator-5554 shell cat /sdcard/mobile-parser.xml
```

Не выполняйте dump параллельно с экстрактором. Сопоставляйте XML с PNG: текст, clickable, scrollable, границы и вложенность. Меняйте ожидания/селекторы по наблюдаемому экрану, а не добавляйте бесконечные задержки. Существующие пределы: 50 прокруток поиска категории/подкатегорий, 200 экранов товаров; повтор текстов и координат завершает прокрутку. Короткий список без прокручиваемого элемента завершается после сохранения первого экрана. При поиске категории сначала проверяется наличие нужного элемента, а затем возможность прокрутки. Если категория отсутствует и список не прокручивается, выдаётся `Категория не найдена: <полный путь>`; категория не пропускается молча.

## Замер полного сбора

```powershell
npm run benchmark:pobeda
```

Перед замером выключите нужный эмулятор штатно и дождитесь его исчезновения из `adb devices`. Обёртка отслеживает дочерние процессы нового запуска; уже работающий отдельный эмулятор не входит в это дерево. Рабочий конфиг не меняется, его копия сохраняется в `outputs/pobeda/benchmark-<время>/config.snapshot.json`.

В этой папке: `events.jsonl` — этапы, заходы в категории, скроллы, скриншоты и команды ADB; `resources.jsonl` — выборки ресурсов каждые 2 секунды; `benchmark.json` — время, код завершения и параметры компьютера; `stdout.log`, `stderr.log`, `run.log` — журналы. Можно задать период выборки через `powershell -ExecutionPolicy Bypass -File scripts/benchmark-pobeda.ps1 -SampleSeconds 1`.

UI-запросы = заходы в категории + успешные скроллы. Нажатия включают эти заходы, поэтому не добавляйте их повторно к этому итогу. ADB-команды учитываются отдельно: это локальные операции, а не HTTP-запросы приложения. Working set и private bytes имеют разный смысл; пики выборочные, кратковременные процессы могут не попасть в измерение. CPU выражается в эквиваленте занятых логических ядер. Ошибочный или частичный запуск не подтверждает ресурсы полного сбора и не подходит для расчёта производительности параллельных потоков.

Типовые проблемы:

- `ENOENT` для `adb.exe`/emulator — проверьте локальный SDK и рабочую директорию. `ADB_PATH` заменяет только ADB, не путь emulator/AVD.
- Порт занят другим AVD — освободите порт либо задайте `ANDROID_SERIAL=emulator-5556` до запуска; нужный AVD выбирается через `ANDROID_AVD`.
- Магазин не найден — сравните строку в UI и конфиг. Уже выбранный магазин может отсутствовать в поиске; подтверждение проверяется на главной.
- Категория/товары не загрузились — приложите соответствующий участок `run.log`, PNG и XML, укажите адрес и конфиг без секретов.
- Не появляется клавиатура — запуск через общий `Android.start` включает экранную клавиатуру и отключает рукописный режим. Для ввода с ПК проверьте `hw.keyboard=yes` и перезапуск AVD.

## Проверка изменений

Минимум: `npm run check` и `npm test`. Для изменений UI обязательно отдельно проверяйте живой запуск: выбранный адрес, конечные категории, конец прокрутки, результаты, файл лога и выключение. Не называйте статическую проверку подтверждением Android-сценария. Не обновляйте SDK, зависимости и пользовательский конфиг без необходимости.
