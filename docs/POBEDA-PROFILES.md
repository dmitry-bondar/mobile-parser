# Победа: отдельный профиль на каждый адрес

Этот режим предназначен для своих/разрешённых аккаунтов и не гарантирует отсутствия ограничений приложения. Профили содержат авторизацию; не отправляйте их в Git и не передавайте SMS-коды. Настройки Google-аккаунта и вход в Победу выполняются вручную.

## Привязка

В основном `src/extractors/pobeda/config.json` у каждого адреса добавлено `avd`: `pobeda-store-01`…`pobeda-store-20`, по порядку адресов. Первому соответствует Медынь, второму — Рязань, М-5 Урал. Телефоны, SMS и учётные данные в конфиге не хранятся. При необходимости меняйте именно поле `avd`, не переименовывайте каталоги руками. Один профиль нельзя закрепить за несколькими адресами.

Старые `npm run pobeda` / `npm run pobeda:parallel -- android-v1 2` продолжают использовать общий шаблон и несколько адресов на аккаунт. Для раздельных профилей используйте **только новые команды ниже**.

## Первичная проверка двух профилей

Все сборы и постоянные эмуляторы должны быть выключены. Перед подготовкой сохраните резервные копии своих выключенных профилей: подготовка изменяет выбранный магазин в их приложении. Не очищайте данные и не выходите из аккаунтов.

На сервере:

```powershell
cd C:\mobile-parser
git pull --ff-only
npm ci
npm run pobeda:profiles:prepare -- 1 --limit 2 --gpu swiftshader --no-vulkan
```

Последняя команда **не собирает товары**. По очереди открывает постоянные профили первых двух адресов, проверяет вход, автоматически выставляет только закреплённый магазин, подтверждает адрес на главной и выключает профиль. Уже совпавший адрес не меняется. Авторизация и постоянные AVD сохраняются. В общей таблице и `status.json` режим обозначен как подготовка. Дождитесь завершения команды и проверьте, что оба задания имеют статус «Готово».

Затем можно проверить реальный сбор первых двух адресов:

```powershell
npm run pobeda:profiles -- 2 --limit 2 --gpu swiftshader --no-vulkan
```

На этом шаге из каждого постоянного профиля создаётся независимая временная копия. Если адрес на главной не соответствует закреплённому, экстрактор **не переключает магазин**, а сообщает ошибку задания и предлагает повторить подготовку. Не запускайте сбор до успешной подготовки.

## Все двадцать адресов

После проверки первых двух:

```powershell
# Подготовить все 20 постоянных профилей последовательно, без сбора.
npm run pobeda:profiles:prepare -- 1 --gpu swiftshader --no-vulkan

# Только если подготовка завершилась без ошибок — собрать все адреса двумя потоками.
npm run pobeda:profiles -- 2 --gpu swiftshader --no-vulkan
```

Вторая команда — очередь из 20 заданий с максимум двумя работающими одновременно. У каждого задания ровно один адрес и его собственный профиль. По завершении задания поток ждёт остановки эмулятора и очистки временной копии, затем берёт следующий профиль. Порты 5554 и 5556 используются повторно, но никогда не двумя заданиями одновременно. Начало второго потока отложено на 25 секунд для снижения начальной нагрузки.

## Результаты и ошибки

Общая таблица показывает номер задания, профиль, адрес и статус. В `outputs/pobeda/parallel-…/` находятся общий `status.json`, история `progress.jsonl` и логи `worker-N.log`, где N — номер задания/профиля в выбранном списке, а не номер занятого порта. В отчёте указаны каталоги результатов каждого задания. JSON, PNG, ошибки и `emulator.log` сохраняются отдельно; старые результаты не подмешиваются.

После подготовки удаление постоянного AVD не выполняется. После сбора удаляется только временный `mp-run-…`; постоянный профиль остаётся неизменным. Сбор из временной копии не обновляет постоянную авторизацию. При истечении сессии остановите задания, вручную войдите в нужный постоянный профиль, выключите его и повторите подготовку/сбор. Нет автоматической регистрации аккаунтов, получения SMS, смены номеров, прокси или сброса идентификаторов.

Ошибка конкретного задания не останавливает очередь остальных профилей. Сохраняются ограничения перезапуска эмулятора и обработки категорий. Не смешивайте подготовку и сбор, старый и новый режимы, ручное редактирование и автоматическую работу с теми же профилями.

Профильный запуск держит `.profile-<имя>.lock` и блокировку занятого порта. После принудительного завершения они могут остаться: сначала проверьте отсутствие соответствующих процессов, затем удаляйте только подтверждённо устаревший lock-файл. При Ctrl+C новые задания не запускаются, а автоматические перезапуски действующих отключаются; дождитесь их завершения/очистки. Не удаляйте каталоги работающих устройств.

`--limit N` выбирает первые N объектов текущего конфига для подготовки или сбора и не изменяет сам конфиг. Для произвольной части можно передать отдельный конфиг через `POBEDA_CONFIG`, сохранив поля `avd`.
