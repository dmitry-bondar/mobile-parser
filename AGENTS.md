# Инструкции для ИИ и разработчиков

Перед изменениями прочитайте `README.md`, затем нужный раздел `docs/SETUP.md` или `docs/DEVELOPMENT.md` и код затрагиваемого экстрактора. Запускайте команды из корня `mobile-parser`.

- Пишите короткий прямой код. Не добавляйте ненужные обёртки, классы, переменные, универсальные фреймворки и зависимости.
- Общие Android/ADB операции — в `src/android.ts` и `src/adb.ts`; логика приложения — в `src/extractors/<name>/`. Это Node.js ESM/TypeScript, импорты локальных TS-модулей используют суффикс `.js`.
- Сохраняйте чужие изменения. `config.json` — рабочие настройки пользователя: не заменяйте адреса/категории тестовыми без разрешения; примеры храните отдельно.
- Используйте `createLogger` для сообщений сценария; ошибки записывайте с объектом Error, а не только message. Не логируйте пароли, токены, SMS-коды и содержимое учётных данных.
- Не удаляйте и не пересоздавайте SDK/AVD, не очищайте данные приложения, не сбрасывайте авторизацию без явного запроса. SDK, AVD, outputs, logs и node_modules не коммитятся.
- Не запускайте живой сценарий без запроса на такой запуск/проверку: он меняет выбранный магазин и выключает эмулятор, включая запущенный вручную. Не управляйте одним Android из двух процессов.
- Не обходите требование авторизации. Пользователь входит вручную. При отказе сохраняйте ошибку и ненулевой код.
- Сохраняйте восстановление клавиатуры и выключение только нужного AVD в `finally`. Не расширяйте управление на чужие устройства.
- Проверяйте UI по фактическим XML и скриншотам; не подменяйте отсутствие товаров таймаутом и не выдавайте частичный сбор за успешный.
- После правок выполните `npm run check` и `npm test`. Отдельно укажите, выполнялся ли живой Android-прогон. Если изменился контракт/запуск, обновите документацию и пример конфига.

Для нового экстрактора следуйте разделу «Новый экстрактор» в `docs/DEVELOPMENT.md`. Нет задачи создавать общий планировщик, сервер, API-интеграцию или параллельный пул устройств без отдельного запроса.
